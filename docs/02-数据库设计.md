# 数据库设计

> 目标平台：Microsoft SQL Server 2016+（V2 实测 SQL Server 2025，兼容级别 170）
>
> 文档版本：V2 ｜ 落款：Zero

---

## 一、设计原则

1. **一张表只描述一个实体**，非主属性完全依赖主键，满足 3NF
2. **业务不变式优先交给数据库**（CHECK / UNIQUE / FK / 触发器），不依赖应用层自觉
3. **事务边界放在存储过程**，保证多步操作要么全部成功、要么全部回滚
4. **查询口径统一走视图**，避免不同页面各写一套 JOIN 导致数字对不上
5. **审计按语义拆表**，一个字段只表达一件事

## 三、表设计

### 3.1 主数据

| 表 | 作用 | 关键约束 |
|---|---|---|
| `Factory` | 生产厂家 | `FactName` 唯一 |
| `Supplier` | 供应商 | `SupName` 唯一 |
| `WarehouseType` | 仓库类型字典 | `TypeName` 唯一；替代原版的自由文本 |
| `Warehouse` | 仓库 | `Size > 0`；`Usage >= 0 AND Usage <= Size`；类型外键 |
| `Item` | 物品 | `(ItemName, ItemType, FactoryID)` 唯一；`Price >= 0` |
| `Staff` | 员工 | `IsActive` 逻辑删除；不物理删除历史经办人 |
| `Customer` | 客户 | `CustomerName` 唯一；销售出库必填，调拨不需要 |

`Warehouse` 只存 `WarehouseTypeID`，类型名称与属性放在字典表，消除"仓库 → 类型名 → 类型属性"的传递依赖。

### 3.2 库位与授权

| 表 | 作用 | 关键约束 |
|---|---|---|
| `WarehouseZone` | 仓库内功能区（存储 / 拣选 / 待检 / 退货 / 冻结） | `(WarehouseID, ZoneCode)` 唯一；类型受 CHECK 约束 |
| `StorageLocation` | 货位（如 A-01） | `(ZoneID, LocationCode)` 唯一；`Capacity > 0`；`IsLocked` 支持冻结 |
| `StaffAssignment` | 员工 × 仓库授权 | 复合主键；双向级联；是权限校验的唯一依据 |

库位挂在库区下，库区挂在仓库下，形成"仓库 → 库区 → 货位"三级。库存只落在货位，不直接落仓库。

### 3.3 库存与流水

| 表 | 作用 | 关键约束 |
|---|---|---|
| `Storage` | 库存单元 | `UNIQUE (ItemID, WarehouseID, SupplierID, BatchNo, LocationID)`；`Storing >= 0`；有效期必须晚于生产日期 |
| `Record` | 出入库流水 | 类型受 CHECK；`OperationQuantity > 0`；调拨必须成组，非调拨不得带组号；来源类型受 CHECK |
| `StockAudit` | 库存变动审计 | `AfterQty = BeforeQty + ChangeQty`；记录批次、货位、来源流水 |
| `PermissionAudit` | 权限变动审计 | 动作受 CHECK；记录操作人与时间 |

**为什么库存唯一键是五元组**：同一物品、同一仓库、同一供应商，仍可能有多批不同批次；同一批次也可能分放两个货位。只有把批次与货位纳入键，才能做到批次级扣减与货位级拣货。

**流水来源字段**：

```sql
SourceType    NVARCHAR(20)  -- 入库单 / 出库单 / 调拨单 / 盘点单 / 手工 / 调拨
SourceOrderID INT           -- 单据主键
SourceLineID  INT           -- 单据行主键
```

`SourceOrderID` 与 `SourceLineID` 不建外键，是因为它们指向四类不同的单据表；由 `CHECK` 约束取值，由存储过程保证配对正确。

### 3.4 作业单据

| 表 | 作用 | 关键约束 |
|---|---|---|
| `InboundOrder` | 入库单头 | 单号唯一；类型与状态受 CHECK；状态：草稿 / 待收货 / 部分收货 / 已完成 / 已取消 |
| `InboundOrderLine` | 入库单行 | `ReceivedQty <= PlannedQty`；记录批次、效期、目标货位 |
| `OutboundOrder` | 出库单头 | 单号唯一；状态：草稿 / 待拣货 / 拣货中 / 已发货 / 已完成 / 已取消 |
| `OutboundOrderLine` | 出库单行 | `PickedQty <= PlannedQty` |
| `StocktakeOrder` | 盘点单头 | 单号唯一；可按仓库或库区盘点 |
| `StocktakeLine` | 盘点单行 | `Variance` 为计算列；未录入实盘数时为 `NULL` |
| `TransferOrder` | 调拨单头 | `SrcWarehouseID <> DstWarehouseID`；记录发货人与收货人；状态：待发货 / 部分发货 / 已完成 / 已取消 |
| `TransferOrderLine` | 调拨单行 | `ShippedQty <= PlannedQty` |

单据行统一使用 `ON DELETE CASCADE`：删除单头时明细随之删除，避免孤儿行。库存流水不级联删除，历史必须保留。

## 四、范式说明

所有表满足第三范式：

- `Storage` 的候选键为五元组，`Storing`、`LastUpdate` 完全依赖整个键，不存在部分依赖
- `Warehouse` 原本把类型名称作为字符串存储，与 `WarehouseID` 构成传递依赖，已拆为 `WarehouseType` 字典表
- 审计表不再复用字段承载多种语义，每个属性含义唯一
- 单据头与单据行分离，客户 / 供应商 / 仓库等描述信息只存一份，行表只存外键与数量

## 六、存储过程

### 6.1 清单

| 过程 | 入参要点 | 完成的事 |
|---|---|---|
| `sp_PostOperation` | 物品、仓库、供应商、类型、数量、经办人 | 权限 → 库存 / 库容 → 写流水（触发器同步库存） |
| `sp_TransferStock` | 源 / 目标仓库、物品、供应商、数量、双方经办人 | 双向权限 → 锁库存 → 两条同组流水 |
| `sp_ReceiveInbound` | 单据行、数量、货位、批次、效期、经办人 | 剩余待收 → 权限 → 货位归属 → 库容 → 流水 → 回写行 → 推进单头 |
| `sp_ShipOutbound` | 单据行、数量、经办人 | 待发 → 权限 → 库存 → 流水（按 FEFO 选批） |
| `sp_ShipTransfer` | 调拨行、数量 | 双向权限 → 源库存 / 目标库容 → 两条同组流水 → 推进状态 |
| `sp_CompleteStocktake` | 盘点单、经办人 | 逐行比对差异 → 生成盘盈 / 盘亏流水 → 结案 |
| `sp_RecalcWarehouseUsage` | 无 | 按库存重算仓库使用量，用于巡检与修复 |

### 6.2 事务与错误处理模板

```sql
SET NOCOUNT ON;
SET XACT_ABORT ON;

BEGIN TRY
    BEGIN TRANSACTION;

    -- 1. 读取并加锁
    SELECT ... FROM dbo.InboundOrderLine WITH (UPDLOCK, HOLDLOCK) WHERE LineID = @LineID;

    -- 2. 业务校验（失败即 THROW）
    IF @Qty > @Remain
        THROW 50006, N'收货数量超过该行剩余待收数量', 1;

    -- 3. 写流水、回写单据、推进状态

    COMMIT TRANSACTION;
    RETURN 0;
END TRY
BEGIN CATCH
    IF XACT_STATE() <> 0
        ROLLBACK TRANSACTION;
    THROW;
END CATCH
```

约定：

- `SET XACT_ABORT ON`：任何运行时错误自动回滚，不留下半条事务
- 校验失败使用 `THROW` 抛业务错误码，应用层映射为友好提示
- 输出参数在过程开头显式置 0，避免 `NULL + 1` 仍为 `NULL`
- 不在触发器里做需要友好提示的校验

### 6.3 错误码

| 错误码 | 含义 |
|---|---|
| 50001 | 单据 / 行不存在 |
| 50003 | 操作人无权操作该仓库 |
| 50004 | 库存不足 |
| 50005 | 库容不足 |
| 50006 | 数量或状态不合法 |

## 七、触发器

| 触发器 | 触发时机 | 守住的不变式 |
|---|---|---|
| `TR_Record_StockSync` | `Record` INSERT | 有流水必有库存变动；出库按 FEFO 扣减；写 `StockAudit` |
| `TR_Storage_SyncUsage` | `Storage` INSERT / UPDATE / DELETE | 仓库使用量恒等于该仓库库存之和 |
| `TR_Assignment_Audit` | `StaffAssignment` INSERT / DELETE | 权限变更必留痕 |

### 7.1 多行安全

V1 的写法：

```sql
SELECT @ItemID = ItemID, @Qty = OperationQuantity FROM inserted;
```

`inserted` 有多行时只赋值最后一行，其余行被静默丢弃。V2 改为游标逐行处理：

```sql
DECLARE cur CURSOR LOCAL FAST_FORWARD FOR
    SELECT RecordID, ItemID, WarehouseID, SupplierID, OperationType, OperationQuantity
    FROM inserted;

OPEN cur;
FETCH NEXT FROM cur INTO ...;
WHILE @@FETCH_STATUS = 0
BEGIN
    -- 逐行扣减、写审计
    FETCH NEXT FROM cur INTO ...;
END
CLOSE cur;
DEALLOCATE cur;
```

### 7.2 FEFO 扣减顺序

```sql
ORDER BY CASE WHEN ExpiryDate IS NULL THEN 1 ELSE 0 END,
         ExpiryDate ASC,
         StorageID ASC;
```

有效期的批次优先出，越临期越先出；无有效期或同效期时按批次先后。只按入库先后出库，会让临期货积压。

### 7.3 使用量同步

`TR_Storage_SyncUsage` 只重算受影响仓库，不做全表扫描：

```sql
UPDATE w
SET WarehouseUsage = ISNULL((SELECT SUM(Storing) FROM dbo.Storage s
                             WHERE s.WarehouseID = w.WarehouseID), 0)
FROM dbo.Warehouse w
WHERE w.WarehouseID IN (SELECT WarehouseID FROM inserted
                        UNION SELECT WarehouseID FROM deleted);
```

配合 `CHECK (WarehouseUsage <= WarehouseSize)`，使用量既不会失真，也不会越界。

## 八、索引

索引跟着查询走，13 条逐条对应真实访问路径，清单见 `v2-wms/sql/02_index.sql`。两处值得说明：

**反向授权查询**

```sql
CREATE INDEX IX_Assignment_Warehouse ON dbo.StaffAssignment (WarehouseID, StaffID);
```

主键是 `(StaffID, WarehouseID)`，"按仓库查有权限的员工"是反向前缀，用不上主键索引。

**筛选索引**

```sql
CREATE INDEX IX_Record_Transfer ON dbo.Record (TransferGroupID)
    WHERE TransferGroupID IS NOT NULL;
```

只索引调拨流水，体积远小于全表索引，专门服务"按组号还原调拨两端"。

外键不会自动建索引，但删除 / 更新父表时 SQL Server 会反查子表；缺索引会导致全表扫描甚至锁升级。主要外键列均建有索引。

## 九、并发控制

库存校验与扣减分处两条语句时，中间存在超卖窗口：

```
事务 A：SELECT 库存 = 10  → 判断可出 10
事务 B：SELECT 库存 = 10  → 判断可出 10
事务 A：INSERT 出库 10    → 库存 0
事务 B：INSERT 出库 10    → 库存 -10
```

V2 在读取待发数量、源库存、目标库容时统一加锁：

```sql
SELECT @Available = ISNULL(SUM(Storing), 0)
FROM dbo.Storage WITH (UPDLOCK, HOLDLOCK)
WHERE ItemID = @ItemID AND WarehouseID = @WarehouseID;
```

`UPDLOCK` 阻止其他事务取得更新锁，`HOLDLOCK` 保持范围锁到事务结束，把"读取—判断—写入"圈进同一临界区。

## 十、已知限制

- **每日库存快照未做**：当前趋势看的是流水，无法精确还原历史每日水位；不做"当前库存减后续净流入"的近似反推，避免形状失真
- **质检流转未实现**：已建"待检区"库区，但"待检 → 合格转存储"的状态机未落地
- **权限粒度到仓库**：未细化到物品类别
- **单据编号按日序列**：高并发下需改为序列对象或加锁生成
