## 二、数据库层：`db_smoke.py`

### 2.1 覆盖场景

| 编号 | 验证点 | 说明 |
|---|---|---|
| C1 | 入库后库存 +10 | 存储过程写流水，触发器同步库存 |
| C1 | 入库产生 1 条库存审计 | `StockAudit` 与流水一一对应 |
| C1 | 审计记录变动前后值 | `AfterQty - BeforeQty = 10` |
| C1 | 仓库使用量同步 +10 | `TR_Storage_SyncUsage` 生效 |
| C2 | 出库优先扣最早批次 | 按 `StorageID` 升序扣减 |
| C3 | 无权限员工被拒绝 | 期望错误码 50003 |
| C4 | 超量出库被拒绝 | 期望错误码 50004 |
| C5 | 数量为 0 被拒绝 | 期望错误码 50006 |
| C6 | 调拨生成 2 条同组流水 | `TransferGroupID` 一致 |
| C6 | 源仓库扣减 3 | 调拨出扣减、调拨入增加 |
| C7 | 超量调拨被拒绝且无残留 | 事务回滚，不留下半条流水 |
| C8 | `StockAudit` 满足 `After = Before + Change` | 审计不变式 |

### 2.2 测试设计要点

**先提交上下文，再测失败路径**

存储过程内的 `ROLLBACK` 会连带回滚调用方未提交的操作。测试在进入失败用例前先提交已有改动，否则会把前面的正常数据一起回滚，导致后续断言错乱。

**失败用例只断言"错误码 + 无残留"**

不依赖具体错误文本，避免 SQL Server 语言版本差异导致误判。

**测试结束回滚**

成功路径的数据在测试结束时统一回滚，保持数据库干净；失败路径由存储过程自身回滚。

### 3.2 覆盖的完整链路

```
创建入库单（2 行）
  → 收 60 → 状态"部分收货"
  → 再收 40 → 状态"已完成"
创建出库单
  → 发货 30 → FEFO 扣减 → 状态"已完成"
创建盘点单
  → 录实盘（盘亏 5）
  → 结案 → 生成盘亏流水
  → 再次结案 → 拒绝
```

这条链路同时验证了：单据状态机、分批作业、库存同步、FEFO、盘点差异、重复操作防护。

## 五、执行方式

```bat
cd v2-wms

.venv\Scripts\python.exe tests\db_smoke.py
.venv\Scripts\python.exe tests\wms_smoke.py
.venv\Scripts\python.exe tests\test_service.py
```

预期输出末尾：

```
通过 12/12
通过 14/14
通过 14/14
```

退出码：全部通过为 0，有失败为 1，可直接接入 CI。

### 5.1 前置条件

- `WarehouseDB_V2` 已按 `sql/01~06` 建好
- `db.env` 或环境变量指向正确实例（`warehouse/config.py` 会自动读取项目根目录的 `db.env`）
- 数据库中存在可用的物品、仓库、员工授权（`06_seed.sql` 已提供）

### 5.2 失败后的处理

数据库测试会写入数据。若中途失败，可能留下未回滚的记录，建议重建数据库后再跑：

```bat
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\01_schema.sql"
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\02_index.sql"
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\03_views.sql"
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\04_procedures.sql"
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\05_triggers.sql"
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\06_seed.sql"
```

## 八、测试带来的两个实际收益

1. **发现 `SCOPE_IDENTITY()` 在 SQLAlchemy + pyodbc 下返回 `NULL`**
   建单时单头插入成功但主键为空，明细插入撞 NOT NULL 约束。改用 `OUTPUT INSERTED.OrderID` 后解决。这个问题只有走 repository 层实测才会暴露，直接写 SQL 的测试覆盖不到。

2. **发现盘点输出参数未初始化**
   `@Adjusted` 传入时为 `NULL`，`NULL + 1` 仍为 `NULL`，调整数永远是空。存储过程开头显式 `SET @Adjusted = 0` 后修复。
