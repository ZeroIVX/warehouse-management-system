## 一、环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（启动脚本为 `.bat`） |
| 数据库 | SQL Server 2016+；V2 实测 SQL Server 2025 Express |
| Python | 3.9 ~ 3.13 |
| ODBC | ODBC Driver 17 for SQL Server |
| 命令行 | `sqlcmd` 在 PATH 中 |

检查：

```bat
python --version
sqlcmd -?
```

若 `sqlcmd` 不存在，安装 SQL Server 时勾选 "Command Line Utilities"，或把 `Tools\Binn` 加入 PATH。

## 二、数据库配置

仓库不保存任何真实服务器、账号、密码。两版的应用与测试都会自动读取各自目录下的 `db.env`（环境变量优先）：

```ini
# SQL Server 实例；命名实例写成 localhost\SQLEXPRESS
WAREHOUSE_DB_SERVER=localhost
WAREHOUSE_DB_NAME=WarehouseDB_V2
# 留空 -> Windows 集成认证
WAREHOUSE_DB_USER=
WAREHOUSE_DB_PASSWORD=
```

首次双击 `启动.bat` 时，如果连接失败且没有 `db.env`，脚本会引导输入实例与认证方式，并写入本地 `db.env`。该文件已被 `.gitignore` 排除。

### 2.3 依赖安装源

启动脚本在未设置 `PIP_INDEX_URL` 时默认使用阿里云镜像，便于国内网络首次安装。需要换源时：

```bat
set PIP_INDEX_URL=https://pypi.org/simple
```

再运行 `启动.bat`；已设置的环境变量优先于脚本默认值。

也可以手动复制模板：

```bat
copy v2-wms\db.env.example v2-wms\db.env
```

### 2.1 认证方式

| 方式 | 配置 | 前提 |
|---|---|---|
| Windows 集成认证 | 用户名留空 | 当前 Windows 账号有数据库权限 |
| SQL 身份验证 | 填用户名与密码 | 实例启用混合模式，账号已创建 |

启用混合模式：SSMS → 实例属性 → 安全性 → "SQL Server 和 Windows 身份验证模式" → 重启服务。

### 2.2 数据库名

| 版本 | 默认库名 |
|---|---|
| V1 | `WarehouseDB_V1` |
| V2 | `WarehouseDB_V2` |

两版使用独立数据库，可同时运行、互不干扰。

## 三、一键启动

### 3.1 V1

```
双击 v1-legacy\启动.bat
```

流程：

1. 读取 `db.env`，缺省 `localhost` + 集成认证
2. 检测 `WarehouseDB_V1` 是否存在
3. 不存在时询问是否创建，执行 `sql/01_schema.sql` 与 `sql/02_seed.sql`
4. 创建 `.venv` 并安装依赖（仅首次）
5. 启动 Streamlit，默认 <http://localhost:8501>

### 3.2 V2

```
双击 v2-wms\启动.bat
```

流程与 V1 类似，建库时依次执行：

```
01_schema.sql      22 张表
02_index.sql       13 个索引
03_views.sql       13 个视图
04_procedures.sql  7 个存储过程
05_triggers.sql    3 个触发器
06_seed.sql        主数据、库区货位、库存批次
07_demo_data.sql   近 14 天演示流水
08_demo_orders.sql 演示单据与盘点单
```

默认 <http://localhost:8502>。

> `01_schema.sql` 含 `DROP DATABASE WarehouseDB_V2`。启动脚本只在数据库不存在时调用建库；手动执行前请确认不是正式库。

### 3.3 端口冲突

两版默认端口不同，可并行。若端口被占用，修改脚本中的 `PORT`：

```bat
set "PORT=8502"
```

或手动启动时加 `--server.port 8503`。

## 四、手动运行

### 4.1 V2

```bat
cd v2-wms
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

:: 建库（按顺序；01 会重建同名库）
for %f in (01_schema 02_index 03_views 04_procedures 05_triggers 06_seed) do ^
  sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\%f.sql"

:: 可选演示数据
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\07_demo_data.sql"
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "sql\08_demo_orders.sql"

.venv\Scripts\python.exe -m streamlit run app.py --server.port 8502
```

SQL 身份验证时把 `-E` 换成 `-U 用户名 -P 密码`。

### 4.2 V1

```bat
cd v1-legacy
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

sqlcmd -S "localhost" -E -C -b -Q "IF DB_ID(N'WarehouseDB_V1') IS NULL CREATE DATABASE WarehouseDB_V1;"
sqlcmd -S "localhost" -E -C -b -I -f 65001 -d WarehouseDB_V1 -i "sql\01_schema.sql"
sqlcmd -S "localhost" -E -C -b -I -f 65001 -d WarehouseDB_V1 -i "sql\02_seed.sql"

.venv\Scripts\python.exe -m streamlit run app.py --server.port 8501
```

## 五、重建数据库

### 5.1 V2

```bat
sqlcmd -S "localhost" -E -C -b -I -f 65001 -i "v2-wms\sql\01_schema.sql"
```

`01` 会删除并重建 `WarehouseDB_V2`，随后按顺序执行 `02` ~ `08`。

### 5.2 V1

```bat
sqlcmd -S "localhost" -E -C -b -Q "ALTER DATABASE WarehouseDB_V1 SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE WarehouseDB_V1;"
```

再执行建库与种子脚本。V1 的 `01_schema.sql` 不建库，需先 `CREATE DATABASE`。

## 七、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `sqlcmd 不是内部或外部命令` | 未安装命令行工具或不在 PATH | 安装 Command Line Utilities，或把 `Tools\Binn` 加入 PATH |
| 连接失败，提示证书 | Express 使用自签证书 | 连接串已带 `TrustServerCertificate=yes`；手动执行时加 `-C` |
| 登录失败 | 未启用混合模式 / 账号无权限 | 改用集成认证，或启用混合模式并授权 |
| `Cannot open database` | 库未创建 | 用启动脚本建库，或手动执行 `01_schema.sql` |
| 建库脚本报 "数据库正在使用" | 有活动连接 | 关闭应用与 SSMS 查询窗口，或让 `01` 的 `SINGLE_USER` 处理 |
| 页面空白 / 一直加载 | Streamlit 进程未起或端口错误 | 看控制台输出，确认端口与 `http://localhost:端口` |
| 改了代码但页面没变 | 旧进程占用端口，新服务被挤到其他端口 | 结束占用端口的 Python 进程后重启 |
| `ModuleNotFoundError` | 依赖未安装或用了系统 Python | 用 `.venv\Scripts\python.exe` 启动，重跑 `pip install -r requirements.txt` |
| 首次装依赖很慢或卡住 | 默认源不可达 | 设置 `PIP_INDEX_URL` 切换镜像后重试；已下载的包会走本地缓存 |
| 中文乱码 | 终端编码不是 UTF-8 / GBK | 脚本已设 `PYTHONUTF8=1`；手动运行时设置 `set PYTHONUTF8=1` |

### 7.1 查看端口占用

```bat
netstat -ano | findstr :8502
```

按 PID 结束进程：

```bat
taskkill /PID <PID> /F
```

### 7.2 确认数据库对象

```sql
USE WarehouseDB_V2;
SELECT (SELECT COUNT(*) FROM sys.tables)     AS 表,
       (SELECT COUNT(*) FROM sys.views)      AS 视图,
       (SELECT COUNT(*) FROM sys.procedures) AS 存储过程,
       (SELECT COUNT(*) FROM sys.triggers)   AS 触发器;
```

预期：22 / 13 / 7 / 3。

## 八、部署说明

本项目定位是本地演示与课程项目，不建议直接暴露公网。若需部署到服务器：

1. 使用独立的低权限数据库账号，只授予所需 schema 的执行权限
2. 通过环境变量注入连接信息，不落盘明文
3. Streamlit 加反向代理与 HTTPS
4. 关闭 `--server.headless false` 的自动开浏览器行为
5. `01_schema.sql` 的 `DROP DATABASE` 必须从生产脚本中移除
